# UniBlue coverage expansion for home and SOHO networks

**Build the observation cache and the per-host port planner before adding rule packs.** The current CLI adds the union of rule ports to every eligible host's TCP sweep. A hundred rules against one cached IPP, UPnP, or DNS-SD description can instead cost one request, and many inventory rules can cost zero. The most valuable findings are about **who can reach which function**. A printer advertising IPP, a camera answering discovery, and a dashboard rendering its login page each establish identity. An effective anonymous-admin grant, an unrestricted storage export, or a camera proxy publishing its internal listener establishes a different and more consequential fact.

This is a research and implementation report against checkout `d86a981`. The catalog specifies candidate assertions and the evidence needed to enable them. Documentation and source were reviewed. No traffic was sent to household devices, and the proposed packet budgets and compatibility assumptions have not been measured on hardware.

**Scope.** The catalog has 228 entries across nine categories. It includes new candidates, refinements of existing UB rules, and controls that can only be evaluated using owner-supplied evidence.

### Discovery contracts

Scope each collector to an explicitly monitored interface and network. Start with UniFi inventory, ACLs, forwards and observed service announcements. A monitor on one switch port sees only traffic delivered there. Multicast reflectors, IGMP snooping, sleeping radios, Wi-Fi client isolation, IPv6 link scope and VLAN boundaries change visibility. Record the **observer network** on every result. An ACL-derived path is predicted reachability. A response observed from a guest VLAN establishes reachability from that vantage. A WAN forward is configured exposure until its effective firewall and address family are accounted for.

### Data model, evaluation and safety

1. **Model facts per endpoint.** Add a typed endpoint key `(network, observer, address, IPv6 zone, transport, port, service instance)` and observations carrying source, first/last seen, expiry, proof type and sensitivity. Maintain separate TCP reachability, UDP response, advertised service and locally configured listener states. One packet can describe a bridge and several child devices. Keep the child/service identity separate from the bridge MAC. Never move an observation across DHCP lease generations without confirming identity.
2. **Plan once per host.** Keep a small explicit seed list. Index rules by service type, protocol, HTTP fingerprint, OID prefix, model and known port. Passive observations, existing Nerva facts, UniFi per-host hints, or owner inventory can schedule one targeted candidate. Use the advertised scheme and port, including nonstandard HTTPS. A rule mentioning 9380 must add zero connections on an unrelated host. For legacy v1 rules keep an explicit compatibility pack during migration. Remove universal port merging from scan, check-test and monitor paths deliberately.
3. **Cache the observation, evaluate the rules locally.** Coalesce identical requests by device generation, observer, transport, operation, arguments and authentication context. Never reuse authenticated data to prove anonymous access. Cache only parsed safe facts. Coalesce simultaneous full-scan and live-event work across worker pools. Invalidate on link/lease/service changes, firmware changes or policy changes. An ACL change recalculates severity without a fresh device request unless the vantage proof expired. Keep stale/unknown across missed announcements or budget skips. Require a fresh contrary observation before resolving a finding.
4. **Proposed starting budget.** One outstanding exchange per physical device across discovery, Nerva, fingerprinting and checks. On an ordinary scan allow up to two **incremental** unicast metadata operations per newly identified device, at least 200 ms apart, with a 1 s deadline each, no retry. Skip active verification on known sleeping/battery-operated units. One optional multicast question per protocol per interface per 15 minutes, jittered and disabled if excluded devices share the link and must receive no scanner traffic. Cap pending discoveries, e.g. 128 per interface, with overflow counted. Back off unanswered candidates for 30 minutes. Honor shorter protocol TTLs for freshness without automatically re-probing. These are initial limits to test, not throughput measurements.
5. **Constrain the operation in Go.** `udp`, `tcp-exchange`, `snmp`, `upnp`, `mdns`, `tls`, `http-metadata`, `config-fact` and `observe` are useful YAML types if they select a reviewed operation ID. Its Go descriptor fixes transport, request fields, permissible service identity, parser, byte/deadline caps, and side effects. Request bytes, arbitrary SOAP/RPC methods, sockets and scripts do not belong in community YAML. For example, allow IPP Get-Printer-Attributes with a short attribute allowlist even though IPP uses HTTP POST. A GET endpoint that toggles a relay is unsafe regardless of the verb.
6. **Enforce the same policy before every network write.** Include stage-one banners, TLS ClientHello, Nerva plugins, imported rules and stage two. Make TCP 9100 connect-only at most, and block all application bytes on any endpoint advertised as a print-data stream, including nonstandard ports. Use the same sink guard for LPD/job ports and serial-over-IP bridges. A 9100 node-exporter can be recognized from owner inventory without overriding this default. Never register a controller, initiate TV pairing, wake a sleeping unit, open a media or desktop session, acquire a device lock, generate a scan/print job, try passwords, modify port mappings, select a PLC register range, or replay an advisory bypass. Active packets can still wake a device or generate a log entry. Make passive-only the supported mode for a zero-transmission requirement.
7. **Pin and bound every advertised URL.** Decode and canonicalize as a URL once, require HTTP(S), a permitted metadata resource, no userinfo or fragments, and a host that independently maps to the same enrolled device on that interface. Dial the pinned address, recheck exclusions and special-address policy, disallow redirects, proxies, cross-device URLs, off-link targets and XML external references. A same-IP URL can still refer to a state-changing endpoint. For unrecognized firmware use announcement-only until its description path is approved. Limit redirect count to zero, body to e.g. 16 KiB for metadata and 64 KiB for XML descriptions, after decompression. Cap headers, nesting, XML tokens, counts, and per-datagram size. Parse XML by namespace. Use an explicit end-of-document/truncation result. The owner reconciles conflicting SSDP LOCATION, DNS-SD SRV and UniFi IP/MAC bindings. Until then retain a passive conflict fact and schedule zero network requests.
8. **Make predicates composable and verifiable.** Add scoped `all`, `any` and `not`, same-service joins, and transport-aware `ports_all`. Add selectors for service instance/type, TXT allowlists, UPnP device/service URNs, SNMP enterprise subtrees, certificate dates, Nerva protocol and firmware. For HTTP multi-path alternatives allow a short ordered list of approved metadata operations and stop after a conclusive match, auth challenge, or budget limit. Allow only narrow request headers such as static `Accept`. Forbid Host overrides, forwarding/auth headers, cookies and values interpolated from responses. A DNS-SD SRV endpoint may legitimately have no matching TCP precondition when the rule is observational.
9. **Extract facts, not response dumps.** Support a bounded JSONPath subset of object keys and indexed array elements, QName-aware XML paths, and precompiled Go RE2 named captures. Compare typed numbers/booleans, reject duplicate or ambiguous keys in security predicates. `not_contains` requires a complete positive product-typed response. HTML fallback, an auth page, timeout, redirects, and truncation produce unknown. Version comparisons use the existing [version code](../internal/cve/version.go) where the vendor format fits. Add explicit firmware-train, date-code and distribution-backport comparators elsewhere. An unknown model, hardware revision or train cannot satisfy a fixed-version range.
10. **Carry the proof into reporting.** Replace the generic “without required authentication” success message with a schema-validated fact template. Preserve protocol and observer in finding identities and migrate legacy TCP keys without alert churn. Supersede only a weaker claim about the *same property*. Keep raw bodies, stream URLs, tokens, serials, person/room names, SSIDs, share paths and private SANs out of logs, state, UI events and webhooks. Extract allowlisted fields before persistence. Use keyed local pseudonyms only where longitudinal matching requires them.

**Proposed v2 YAML.** Each operation below has a fixed Go implementation. The example reuses one benign version/identity read across all HomeWizard v1 rules. A separate rule can join the cached identity to trusted topology or permission facts.

~~~yaml
schema: 2
id: UB-HW-V1-IDENTITY
title: HomeWizard P1 meter advertises its v1 LAN API
category: service-inventory
severity: info
safety: read-only
preconditions:
  any:
    - mdns_type: _hwenergy._tcp.local.
    - mdns_type: _homewizard._tcp.local.
probe:
  type: http-metadata
  endpoint: matched_service
  operation: homewizard.v1.device_info
  request_headers:
    Accept: application/json
  match:
    status: [200]
    json:
      - {path: "$.api_version", equals: "v1"}
      - {path: "$.product_type", equals: "HWE-P1"}
  evidence:
    - {name: firmware, path: "$.firmware_version", format: vendor_version}
~~~

The operation is `GET /api` on the verified same-device endpoint, with no credentials or cookies. Persist the firmware and product match and discard the serial. An observed P1 meter is Info. A separate unauthenticated measurement from a guest-network observer can justify Medium because power data can reveal occupancy. [HomeWizard v1 device information](https://api-documentation.homewizard.com/docs/v1/api)

### Acceptance criteria

Replay synthetic or consented, sanitized fixtures through the same parser used by scan, check-test and monitor. For every promoted rule include a positive, an authenticated/locked response, a generic look-alike and a truncated/error case. For broadcasts include duplicate, stale, forged/cross-host and reflected replies. Prove at the socket boundary that a fake raw printer receives **zero application bytes** from every stage. Test cancellation and a concurrent full/live scan against the same physical device. A topology-only update should send zero device packets. Benchmark cold and warm scans against the same seed list and fixtures with 0, 100 and 1,000 additional rules. Record p50/p95 wall time, sockets, datagrams, bytes and timeouts by host. Set the release gate to no increase in warm-scan requests for cached facts and no growth in baseline dials on irrelevant hosts. Keep a packet-capture regression fixture for each audited binary codec.

**How to implement the tables.** Every row names a predicate, the endpoint or passive source, the strongest supported conclusion, base severity, and the missing deployment fact a CVE feed cannot supply. The row IDs are research references, independent of production check IDs. A grouped manufacturer row uses one wire signature shared by those products. A family label alone never confirms a vulnerability.

- **I** = identity/placement only. **R** = a specific credential-free metadata or telemetry read from the recorded observer. **P** = confirmed configuration or protocol property from effective policy, the negotiated response, or trustworthy existing audit evidence. **V** = vendor advisory applicability by exact model/build. A grant to anonymous users proves a permission only for the route, role and observer covered by that grant.
- **Info / Low / Medium / High** are proposed base severities for the exact predicate. An ordinary inventory fact stays Info. Where a row gives two outcomes, the higher level requires the extra predicate in that row. Account for sensitive content, observer VLAN, effective ACLs and established port forwards separately. No category gets Critical simply because a TCP port is open.
- **D** means a valid DNS-SD PTR and matching SRV on UDP 5353. Service names below omit the terminal `.local.` unless specified. Use the SRV port, which is an exact runtime value. **U** means an SSDP advertisement on UDP 1900 plus corresponding device description where needed. **W** means WS-Discovery on UDP 3702 as specified above. **T** followed by a number means TCP and **U** followed by a number means UDP, with or without a slash. HTTP and HTTPS always mean TCP here.
- HTTP signatures assume an already identified same-device service, an unauthenticated request, expected success status (normally 200), a parsed body of the indicated type and the listed product markers. For HTML, use the already cached landing page or explicit owner-bound identity plus the approved path. No default-port scan follows from a catalog entry. A configured service may live behind TLS, a reverse proxy, a path prefix, or an entirely different port.
- **Local / policy / audit** means an operator-supplied, authenticated local settings source, management-plane inventory, or previously generated access audit. Consume only the listed field, permission, log classification or boolean. No active retrieval of photos, directories, command shells, printer secrets, backup images or network-wide credential lists is required. A **fixture gate** means the row remains a candidate until the exact variant is captured and verified. A public health page or an open socket alone cannot qualify as R for sensitive data or P for anonymous control.

**Minimum contract for a policy fact.** Use an opt-in import separate from community YAML. An operator can generate it with local read-only access to a managed system. Bind each record to a collector identity, managed asset, configuration generation, observation time and validity window. Carry the resolved principal, source network, service/operation, protection, outcome and resource sensitivity. Version every product-specific adapter. Keep the original service credentials on the managed system. Confirm source authorization and integrity before trusting a record. An unknown default, unresolved include, ambiguous source IP behind a proxy, or expired audit prevents a confirmed grant.
